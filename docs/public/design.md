# 设计（v2）：一个数字，零配置

> 0.6.0 起生效。上一版把“诚实”做成了很多开关和表格，这一版把它收回成一句话：**看一个数，够了**。

## 1. 一条原则

**打开就是答案，不需要配置。**

用户只想知道“还要多久”。任何需要先理解的设置、标签、表格、开关，都是失败。准确率做不到承诺，就别用复杂度伪装精确。

## 2. 界面（面板就这四层）

```
耗时预估                                    ⋯

约 12m  还需              ← 一眼答案（区间或单点）
预计 14:58 完成            ← 什么时候结束

██████████░░░░░│░░░░       ← 一条进度带：已用 / 剩余区间 / 现在
14:27                15:10 ← 起点与最晚完成时刻

已用 32m · $0.24 · 1.2M   ← 一行事实，不铺表格
```

- 没有开关、没有来源标签、没有百分比表、没有配置项。
- 超估时把“预计完成”换掉，写“已超出初估，按实际进度重新估算”——这是唯一的例外文案。
- 详情、校准数据放在右上角 `⋯` 里，默认不可见。

## 3. 早期不装准

- 只有证据足够（本地样本 ≥8、调用 ≥5、区间高低比 ≤2.2）才显示单点“约 X”。
- 其余显示区间；区间宽就是在说“我还不敢定”。
- 任务一开始就在跑，如果预估跑过了实际用时，直接校正并承认，不硬撑。

## 4. 模型预估：自动，无开关

- 默认开启、默认用当前会话的路由（本来就是这段任务的处理者，不新增外发对象）。
- 预计 5 分钟内结束的任务不调用；长任务或还估不准的任务调用一次。
- 失败、超时、格式不符，一律退回模板，不打扰用户。
- 因此**面板上没有开关**：它要么正确工作，要么安静地退回。

## 5. 配置只在文件里

`config` 仍支持高级用户通过 JSON 调整（阈值、路由覆盖、价格），但**界面不再暴露**。默认值就是产品推荐值。

## 6. 验收

1. 打开面板 3 秒内能读到“还要多久、几点完”。
2. 默认界面零开关、零表格。
3. 长任务不会在开头出现精确的小数字。
4. 超估会自己承认，不显示已经过去的完成时间。

## 7. 明确不做

- 不做配置向导；不做标签体系；不做多维度表格（放详情）。
- 不承诺准确率；不显示伪精确的百分比。
